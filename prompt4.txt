项目目标与产物说明

本项目的目标是：
基于 input.txt 行程描述文件，生成带有交互行程侧栏、地图标记、路线规划的静态文件 output-map.html，用户无需本地服务器即可直接双击打开查看行程地图。

最终生成的 output-map.html 需具备以下能力：

可视化展示每日行程的地点标记（Marker）

支持多日切换

支持交通方式切换（驾车、步行、公交）

自动调用高德路线规划，并展示路线折线

使用分离式结构（地图逻辑放入 src/map.js，HTML单独生成）

美化UI，使侧栏更现代化、清晰、适合展示给用户

使用缓存机制：

地址地理编码缓存（减少API调用）

路线规划缓存（减少重复路线查询）

支持双模式 Key 注入机制（Dev自动注入，Build保留占位符）

🧠 数据处理流水线（作为开发遵循）

生成 output-map.html 必须遵循以下处理顺序：

input.txt
    ↓ parse（解析 DSL）
amap-raw.json（无需输出）
    ↓ geocoding（地址转经纬度）+ 缓存（本地JSON）
output-amap.json
    ↓ HTML模板渲染 + UI填充 + 注入 Key 占位符或真实值
output-map.html


地理编码与路线规划均需使用 缓存优先策略

渲染 HTML 时 map.js 必须以 <script src="./src/map.js"></script> 方式加载

🧭 生成规范：src/map.js
1. 全局暴露（符合你选择的模块模式 #2）

必须包装为 IIFE，并暴露到 window：

(function (global) {
  const AmapTripRenderer = {
    initMap() {},
    renderDays() {},
    renderRoutes() {},
    clearMap() {},
    // ...
  };

  global.AmapTripRenderer = AmapTripRenderer;
})(window);

2. 功能模块必须包含
模块	说明
initMap(container, center)	初始化地图
renderDayList(days)	渲染侧栏 Day 列表
renderMarkers(day)	渲染当天地点 marker
renderRoutes(day, mode)	显示路线，支持驾车/步行/公交
clearMap()	清理图层
setupModeSwitching()	模式按钮逻辑
3. UI 要求

按钮状态切换 .active class

当天行程高亮

地图初始位置使用第一个地点坐标

4. 缓存要求（必须实现）

缓存文件形式留在本地 JSON，可读写：

缓存类型	作用	Key 格式
Geocoding 缓存	减少地理编码 API 调用	address → {lng,lat}
Route 缓存	减少路线规划 API 调用	"${from.lng},${from.lat} -> ${to.lng},${to.lat} (${mode})"
5. 逻辑注意点

地图加载失败要 console.warn，但不阻塞渲染其他天

公交路线需根据城市切换 city

normalizeLocation 输出 {lng,lat} 对象（禁止使用数组）







高德 JSAPI Key 不可直接硬编码在 src/map.js 中，必须按以下模式处理：

✅ Dev 模式（本地开发）

行为：

从 .env 或 config 读取 Key

自动注入 <script src="https://webapi.amap.com/maps?...key=XXXX"></script> 到 output-map.html 的 {{AMAP_JS_KEY_INJECT}}

用户无需手动修改任何文件即可运行

📦 Build / 发布模式

行为：

{{AMAP_JS_KEY_INJECT}} 替换为 占位符：

<!-- 请在此处填入你的高德 Key -->
<!-- <script src="https://webapi.amap.com/maps?v=2.0&key=YOUR_KEY&plugin=AMap.Driving,AMap.Walking,AMap.Transfer"></script> -->


不应包含真实 Key，以防泄露

Key 注入示例（Dev 模式替换）：
<script src="https://webapi.amap.com/maps?v=2.0&key=${AMAP_KEY}&plugin=AMap.Driving,AMap.Walking,AMap.Transfer"></script>


构建脚本应负责决定注入哪种模式版本。

🧠 缓存策略要求（必须实现）

缓存文件存储位置可为根目录 .cache/ 或 data/cache/，推荐使用 JSON 文件。

1. Geocoding 缓存规则

Key 格式："<address>"
Value格式：{ "lng": 121.4737, "lat": 31.2304 }

流程：

若 address 在缓存中 → 直接使用缓存
若未命中 → 调用 geocode API → 写入缓存 → 使用结果

2. Route 缓存规则

Key 格式：

"${from.lng},${from.lat} -> ${to.lng},${to.lat} (${mode})"


Value格式：路线点数组（用于绘制 polyline）

流程：

若路线在缓存中 → 使用缓存绘制路线
若未命中 → 调用路线API → 存入缓存 → 绘制

缓存写入要求：

必须异步写入 JSON（避免阻塞）

不要求合并文件，可使用两个独立的缓存文件：

geocode-cache.json

route-cache.json
